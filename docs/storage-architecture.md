# 저장 구조 원칙 — GitHub 우선 / Supabase 최소화

## 목표
정적 게임 데이터는 GitHub + Vercel 배포물에서 읽고, Supabase에는 로그인 계정의 조작 방지가 필요한 최소 가변 상태만 저장한다.

## GitHub에 저장
- 난이도/웨이브/몬스터/보스 밸런스와 보상표
- 유닛 기본 능력치, 스킬 정의, 성장 공식
- 부적 카탈로그, 등급, 기본 효과, 합산 상한, 강화 공식
- 학습 문제은행 JSON, 출처/라이선스/검증 메타데이터
- 미션/출석/이벤트 정의
- UI 텍스트, 도감, 이미지/오디오 및 정적 리소스
- 앱/게임 버전별 규칙과 밸런스 변경 이력

정적 데이터 때문에 Supabase 테이블을 추가하지 않는다. 밸런스 변경은 Git commit으로 추적한다.

## Supabase에만 저장
- Auth 사용자 식별/세션에 필요한 서버 데이터
- 계정별 지갑: 금화/다이아/티켓/가루
- 계정별 영구 성장: 유닛 Lv/별/카드, 부적 보유/별/Lv, 주인공 성장
- 출석 마지막 수령일/누적, 최초 보상·미션 수령 여부
- 현재/미수령 전투 정산과 중복 요청 방지 request id
- 구매/IAP 영수증 검증 상태(결제 도입 시)
- 계정 삭제에 필요한 사용자 귀속 데이터

## 기기 localStorage
- 비회원 진행
- 로그인 계정의 미전송 임시 스냅샷/충돌 복구본
- 진행 중 전투 결과의 재전송용 임시 데이터
- UI/사운드 같은 기기 설정

localStorage는 유료재화·서버 보상의 최종 원본으로 사용하지 않는다.

## 쓰기 정책
1. 전투 프레임, 웨이브 진행, 몬스터 상태는 서버에 저장하지 않는다.
2. 서버 쓰기는 전투 시작/종료, 보상 수령, 영구 강화/뽑기/구매처럼 가치가 바뀌는 시점만 수행한다.
3. 일반 UI 변경과 전투 중 수치는 로컬에서 처리한다.
4. 동일 요청은 UUID로 멱등 처리하여 재시도 시 중복 지급을 막는다.
5. 정적 정의를 DB에 복제하지 않는다. 서버 검증에 꼭 필요한 최소 상수만 RPC에 둔다.
6. 향후 새 콘텐츠는 먼저 GitHub JSON/JS로 추가하고 DB schema 추가는 계정별 영구 상태가 새로 필요할 때만 허용한다.

## 현재 적용
- 난이도 정의: `public/game-balance.js`
- 부적 정의/효과 공식: `public/talismans.js`
- 학습 문제: `public/learning-data/*.json`
- 계정 진행: Supabase `player_progress`
- 서버 권한 경제/성장: Supabase adventure/talisman RPC
- 게스트/전송 실패 복구: localStorage

## 다음 리팩터링 원칙
기존 Supabase 데이터를 성급하게 삭제하거나 하나의 JSON으로 합치지 않는다. 출시 전에는 데이터 마이그레이션 위험이 더 크다. 대신 신규 정적 데이터의 DB 유입을 막고, API 호출 횟수와 저장 payload를 줄이는 방식으로 단계적으로 최소화한다.
